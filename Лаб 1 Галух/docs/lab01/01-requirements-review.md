# 1. Статичне тестування вимог

Перевірено всі 16 вихідних вимог за однозначністю, повнотою, несуперечливістю, перевірюваністю, здійсненністю та атомарністю. У таблиці наведено порушені ознаки; інші ознаки не є окремими виявленими дефектами. Запропоновані уточнення утворюють узгоджену навчальну базу тестування.

| ID | Тип дефекту | Пояснення й наслідок для тестування | Виправлення або питання |
|---|---|---|---|
| Р-01 | Неатомарність; неповнота | CRUD об’єднує чотири операції; немає валідації й правила видалення. Неможливо визначити очікувані помилки та долю оцінок. | Р-01a: адміністратор створює студента з усіма обов’язковими полями; ПІБ 2–150 символів після trim, email коректного синтаксису, група існує, рік є цілим у межах 2000…поточного року; помилка 422, запис не створюється. Р-01b: адміністратор читає й фільтрує записи за групою. Р-01c: змінює дані з тими самими перевірками. Р-01d: видалення деактивує запис, зберігає оцінки й аудит; нові зміни оцінок неактивного студента заборонені (409). Пропозиція A-01. |
| Р-02 | Неповнота | Не визначено регістр, пробіли й конкурентні запити: однаковий email може бути прийнято двічі. | Перед порівнянням email обрізають зовнішні пробіли та переводять у нижній регістр; унікальність забезпечує БД серед усіх, включно з неактивними, студентів. Дублікат при створенні/зміні: 409. Для двох одночасних створень однакової адреси рівно один успіх 201. A-02. |
| Р-03 | Неперевірюваність | «Швидко» не задає метрики, навантаження й порогу; немає тестового оракула. | Для GET /api/students з пагінацією 50 записів p95 ≤ 500 мс при 150 одночасних сесіях і 5000 студентах; частка 5xx < 1% за 15 хв після 2 хв прогріву. Умови ЯВ-04; поріг є пропозицією A-07. |
| Р-04 | Неповнота | Не визначено тип балів, права на дисципліну й повторне виставлення; незрозуміло, як обробляти дроби та дублікати. | Викладач виставляє цілі бали 0…100 лише студентам власних призначених дисциплін. Поза діапазоном, дробове, null, рядок або відсутнє значення: 422 без зміни даних; чужа дисципліна: 403. Один поточний запис на пару студент–дисципліна; повторний POST: 409, виправлення через PATCH /api/grades/{id}. A-03. |
| Р-05 | Неповнота; неоднозначність | 0 дозволено Р-04, але не має ECTS; «сума» не визначає складові. Немає очікуваного результату на нижній межі. | Єдиний переданий бал є підсумковим, без складання компонентів. Для цілих балів: 90…100 A; 82…89 B; 75…81 C; 67…74 D; 60…66 E; 0…59 Fx. Бал та ECTS зберігаються атомарно. Чи відповідає 0 саме Fx? До відповіді використовуємо A-03. |
| Р-06 | Неповнота | Не описано склад полів і відсутність оцінок; неможливо перевірити порожній кабінет. | Автентифікований активний студент отримує лише свої дисципліни, цілі бали, ECTS та час останньої зміни; GET /api/students/{ownId}/grades повертає 200 і [] за відсутності оцінок, UI показує «Оцінок поки немає». |
| Р-07 | Суперечливість | Дозволяє оцінки одногрупників, але таблиця API дозволяє студенту лише власні. Немає єдиної моделі прав. | Студент не має доступу до персональних даних і оцінок інших студентів, включно з одногрупниками: 403 без чужих даних. Питання: чи потрібна замість цього анонімна статистика групи? До погодження застосовано A-04; юридичний висновок із цього не робиться. |
| Р-08 | Неоднозначність; неповнота | «Розумний час» не задає межі; API виправлення відсутній. Неможливо спроєктувати граничний тест. | PATCH /api/grades/{id} дозволено викладачу призначеної дисципліни, якщо 0 ≤ серверний час UTC − created_at ≤ 48 годин; пізніше 409 без змін. created_at не змінюється після виправлення. Надсилання очікуваної версії обов’язкове, конфлікт версій: 409. Питання: хто виправляє після 48 годин? У межах роботи це заборонено. A-05. |
| Р-09 | Неперевірюваність; нездійсненна абсолютність | «Зручно для всіх» не визначає аудиторії й критеріїв; довести універсальність неможливо. | Принаймні 9 із 10 нових користувачів цільових ролей виконують відповідну типову дію без підказки за ≤ 120 с та без критичної помилки; склад вибірки й сценарії наведені у ЯВ-06. A-07. |
| Р-10 | Неперевірюваність; здійсненність | 24/7 не визначає допустимого простою, періоду і вимірювання; абсолютна безвідмовність нереалістична. | Готовність ≥ 99,5% за календарний місяць; перевірка входу та читання оцінок щохвилини; будь-який невдалий цикл є хвилиною простою, планові роботи включено. ЯВ-05; A-07. |
| Р-11 | Неповнота | Не визначено зміст, порожню групу, права і неправильний формат; немає еталона експорту. | GET /api/groups/{id}/report?format=pdf або xlsx доступний адміністратору; містить групу, дату UTC, ПІБ, дисципліну, бал і ECTS; значення збігаються зі знімком БД на початок експорту. Порожня група: файл із заголовками, неіснуюча: 404, інший формат: 422; інші ролі: 403. A-06. |
| Р-12 | Неперевірюваність; неповнота | Посилання на законодавство без конкретизації актів, підстав обробки та строків не утворює перевірного критерію. | Технічна частина: API перевіряє роль і власника кожного ресурсу (ЯВ-02), передає дані лише через HTTPS, не пише паролі й токени у журнали. Питання замовнику: юрисдикція, правова підстава, строки зберігання, порядок видалення і відповідальний? Відповідність законодавству залишається відкритою, а не доведеною технічними тестами. A-08. |
| Р-13 | Неповнота | Не визначено поля, атомарність і доступ; можна змінити оцінку без достатнього аудиту. | Для створення й кожного виправлення бала в одній транзакції записуються grade_id, actor_id, UTC-час, старе та нове значення, версія й причина виправлення. Невдала операція не змінює оцінку й не створює запис про успішну зміну. Журнал доступний адміністратору лише для читання; API зміни/видалення аудиту немає. ЯВ-03; A-05. |

## Реєстр припущень та відкритих рішень
Це пропозиції автора роботи, які потрібно погодити із замовником. До погодження сценарії мають умовний статус.

| ID | Пропозиція | Що погодити |
|---|---|---|
| A-01 | Обов'язкові поля, роки 2000…поточний, м'яке видалення | Межі полів, життєвий цикл та зберігання |
| A-02 | Унікальність нормалізованої адреси серед усіх записів | Правила регістру й повторного використання email |
| A-03 | Цілі підсумкові бали; 0…59 Fx; викладач лише своєї дисципліни | Оцінку за 0, складові бала, обмеження призначень |
| A-04 | Студент бачить лише власні оцінки | Скасування Р-07 або анонімну альтернативу |
| A-05 | Виправлення до 48 год включно, контроль версії, транзакційний аудит | Строк, процес після строку та поля журналу |
| A-06 | Склад експорту й атомарний знімок | Затверджений макет відомості |
| A-07 | Усі числові цілі ЯВ-04…ЯВ-06; заданий обсяг даних | Реалістичність на цільовій інфраструктурі |
| A-08 | OIDC, керований IdP і політика 3/10/15 | Провайдер, його можливості, правові правила та строки зберігання |

## Доповнення контракту API
Оригінального API недостатньо для Р-08 і Р-13. Пропонується PATCH /api/grades/{id} (score, reason, expected_version), GET /api/audit/grades (адміністратор). Всі захищені маршрути без сесії повертають 401; з недостатніми правами - 403; дозволений запит до відсутнього ресурсу - 404. Студентський GET /api/students (список) заборонений. Викладач читає дані й оцінки лише призначених йому студентів/дисциплін. Операції зі зміни даних іншими ролями заборонені.

У разі тимчасової недоступності БД або відмови запису аудиту операція повертає 503 без часткового збереження. Бал, ECTS, версія і журнал фіксуються однією транзакцією. UI отримує лише підтверджений результат, а після відмови транзакції показує помилку без повідомлення про успіх. Деталізація технічних кодів є запропонованим контрактом, а не твердженням про наявний застосунок.
