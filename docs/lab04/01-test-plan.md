# Тест-план випуску 0.4.0 «Системи управління студентами»

Галух Анна Олександрівна, 63М. Версія основи: викладацький тег `app-lab04`; у цьому репозиторії оновлення влито через PR #4. План складено до дослідницьких сесій ХС-01 і ХС-02; результати оцінено окремо в `06-test-summary.md`.

## 1. Контекст

**Мета:** оцінити, чи можна випускати консоль деканату 0.4.0 без втрати або спотворення студентських даних. **Обсяг:** Р-19 (CSV-імпорт), інтеграція двох консолей через `app/data/group.json`, Р-08 (виправлення оцінки), Р-17 (стипендія), Р-18 (статус), регресія Р-02 (унікальність email) і Р-05 (оцінка ECTS). **Тестова основа:** п. 1.2–1.3 ЛР 4, п. 1.2 ЛР 3, результати `docs/lab03/`, реєстр ризиків ЛР 1 і приклад CSV. **Поза обсягом цього випуску:** REST API, вебінтерфейс, OIDC, PDF/XLSX та навантаження на 5000 студентів — у 0.4.0 цих інтерфейсів ще немає; їхні ризики лишаються для наступних версій. Формальна перевірка прав адміністратора не проводиться: консоль не має автентифікації, це окремий продуктний ризик наступного етапу.

## 2. Припущення та обмеження

Перевіряємо локальний навчальний застосунок на macOS arm64, Python 3.14.10, із тестовою групою `app/data/group.json`. Файли CSV у `docs/lab04/test-data/` не містять реальних персональних даних. Перед кожним прогоном збереження/імпорту відновлюємо вихідний JSON або працюємо з тимчасовою копією. Вимога Р-17 не визначає результат для студентів поза `ACTIVE`; відповідне спостереження трактуємо як питання до замовника. Дефекти викладацького застосунку в цій лабораторній не виправляємо.

## 3. Зацікавлені сторони і комунікація

Студентка готує тестову модель, перевіряє результати й захищає роботу; Codex допомагає виконати відтворювані локальні прогони та оформити матеріали. Викладач оцінює метод і захист. Умовний власник продукту ухвалює рішення про випуск і відповідає на питання до специфікації. Відмови фіксуємо окремими GitHub issues; номери та посилання зводимо в `04-defects.md`. Після кожної сесії записуємо PROOF; підсумковий звіт дає рекомендацію щодо випуску.

## 7. Оцінка трудомісткості і графік

Трибальна оцінка для **всього тестування випуску**, включно із самостійним доопрацюванням після двох академічних годин заняття. Години; `E=(a+4m+b)/6`, `SD=(b−a)/6`. Оцінки незалежні лише приблизно, тому сумарне SD за коренем суми квадратів є орієнтиром.

| Активність | a | m | b | E, год | SD, год |
|---|---:|---:|---:|---:|---:|
| ХС-01: CSV та збереження | 0,33 | 0,42 | 0,67 | 0,45 | 0,057 |
| ХС-02: статуси й дві консолі | 0,42 | 0,50 | 0,75 | 0,53 | 0,055 |
| Повторне відтворення й issues | 0,75 | 1,25 | 2,00 | 1,29 | 0,208 |
| Регресія, RCA, підсумок | 0,50 | 0,83 | 1,50 | 0,89 | 0,167 |
| **Разом** | | | | **3,15** | **≈0,28** |

Послідовність: оновлення й smoke → ХС-01 → відтворення ЛР 3 та issues → ХС-02 → доповнення issues → RCA і звіт. Значення E округлено до 0,01 год, SD — до 0,001; суму раховано з неокруглених значень.

## 8. Пріоритети виконання

Спочатку РП-14 (атомарність імпорту), РП-13 (заборонені статуси), РП-10 (строк виправлення), РП-12 (Fx), далі РП-15 (формат і дублікати CSV), РП-05 (збереження між консолями), РП-01 (ECTS), РП-08 (повідомлення). Якщо час скоротиться вдвічі, перевіряємо принаймні один валідний і три невалідні CSV із перевіркою незмінності JSON, заборонені переходи `GRADUATED/ON_LEAVE`, межу d=14, Fx при середньому ≥90 і повторне читання після збереження. РП-08 переносимо; залишковий ризик документуємо. Наявні відмови рівня 9 все одно блокують випуск, навіть якщо покриття виконано.
