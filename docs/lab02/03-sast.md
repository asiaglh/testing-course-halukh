## Правило `input-to-shell`

Джерело (`source`) — `input()` у `cli.py:67`; дані проходять `course` → параметр `name` у `export_csv` → файл `Path` → `path` в `export_pdf`; стік (`sink`) — перший аргумент `subprocess.run(..., shell=True)` у `report.py:79–82`. Санітизатора, який би зробив shell-виклик безпечним, немає: `.strip()` прибирає тільки пробіли по краях, `Path` не цитує аргументи оболонки. Правило `rules/input-to-shell.yml` **не спрацювало** на preview. Це хибнонегативний результат для заданого шаблону: локальний taint-аналіз у цьому запуску не зберіг зв'язок через функції, повернутий `Path` і перетворення на f-рядок. Цей результат не означає, що ризику немає; його підтверджують S602 і власне правило.

## Власне правило `shell-command-from-fstring`

`rules/shell-command-from-fstring.yml` шукає виклик `subprocess.$FUNC(f"...", ..., shell=True, ...)`: будь-яка функція модуля subprocess із командою з f-рядка, якщо викликана оболонка. Воно **не спрацювало на main** (0), **спрацювало на preview** (`report.py:79`, 1). Це синтаксичний шаблон: виявляє небезпечну комбінацію, але сам собою не доводить, що дані контролює нападник. Ручний аналіз показав шлях від `input()`.
