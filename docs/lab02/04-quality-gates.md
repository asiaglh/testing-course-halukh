# ЛР 2. Контрольні точки якості

| Перевірка | Редактор | Хук перед комітом | CI | Правило `main` | Як можна обійти і що зупиняє зміну |
|---|---|---|---|---|---|
| Ruff check, включно із S і C90 | Можливе розширення Ruff | `ruff-check --fix` | завдання `lint` | обов'язковий статус `lint` | `git commit --no-verify` обходить хук; CI перевіряє опублікований код, ruleset має блокувати злиття при червоному `lint` |
| Ruff format | Можливе розширення Ruff | `ruff-format` | `lint` | `lint` | Локальне форматування можна пропустити, але `--check` у CI фіксує різницю |
| pytest | Можливий запуск у редакторі | Немає | `lint` | `lint` | Тести на preview зелені попри пропущені межі: потрібна рецензія й кращі тести |
| Gitleaks | Не налаштовано | `gitleaks` | Окремого завдання немає | Не обов'язковий окремо | `--no-verify` обходить хук; SAST і рецензія лишаються, але не гарантують пошук кожного секрету |
| Semgrep p/python і `rules/` | Можливе розширення | Не налаштовано | завдання `sast` | обов'язковий статус `sast` | Локальний запуск можна пропустити, але CI з `--error` має блокувати PR |
| Людська рецензія | Код і diff | Немає | Не автоматизується | PR, розв'язання розмов; 0 approvals у одноосібному репозиторії | Автор не може схвалити власний PR; зміст коментарів потрібно перевіряти вручну |

`pre-commit run --all-files` на `main` пройшов: Ruff check, Ruff format, Gitleaks (`evidence/pre-commit-main.txt`). Хуки встановлено лише у локальний клон, бо вони не розповсюджуються через Git; YAML дозволяє кожному учаснику встановити їх. CI конфігурацію опубліковано в `.github/workflows/static-checks.yml`. На [PR №1](https://github.com/asiaglh/testing-course-halukh/pull/1) обидва завдання `static-checks / lint` і `static-checks / sast` завершилися помилкою, як і очікувалося для навчальної гілки з дефектами.

## Три джерела зауважень

- **Людська рецензія:** помилки ECTS на межах (CR-01), ділення на нуль (CR-02), відсутній XLSX (CR-12), невизначений поточний бал (CR-03), персональні дані в логах (CR-08), CSV-формули (CR-09). Частину підтверджено безпечними локальними відтвореннями. Інструменти не мають еталона Р-05/Р-11 чи політики використання даних.
- **Ruff:** зайвий імпорт F401, порівняння з None E711 і форма умовного виразу SIM108 — перевірювані синтаксичні/стильові властивості, для яких людині не варто витрачати час на кожен рядок. Також B006, S105, S602, S110 перетинаються з рецензією.
- **Semgrep:** p/python виявив `shell=True`, власне правило — f-рядок у команді. Вони звужують область, але самі не пояснюють повний шлях з консольного вводу або бізнес-наслідок.

**Хибнонегативний результат:** правило `input-to-shell` дало 0 на preview попри шлях `input()` → `course` → ім'я файлу → `Path` → shell-команда. Обмеження локального аналізу через кілька функцій і перетворень описано в `03-sast.md`.

## Стан захисту гілки

Активний [ruleset `main quality gates`](https://github.com/asiaglh/testing-course-halukh/settings/rules/26800823) застосовується до `main`: забороняє видалення й force push, вимагає PR, актуальну базову гілку, вирішення розмов і успішні перевірки `lint` та `sast` від GitHub Actions. Кількість обов'язкових схвалень — 0, бо автор не може схвалити власний PR. На [PR №1](https://github.com/asiaglh/testing-course-halukh/pull/1) обидві перевірки позначені `Required` і червоні; GitHub показує `Merging is blocked`, а кнопка злиття неактивна. Доказ: [знімок заблокованого PR](img/blocked-pr.png).

Не зливати і не виправляти навчальну гілку `feature/group-report`; на захисті має лишитися відкритий PR із дефектами й рецензією.
