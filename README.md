## Використання ШІ

OpenAI Codex допоміг проаналізувати навчальний код, зібрати локальні докази, підготувати чернетку коментарів і пояснення перевірок. Рецензію потрібно перевірити самостійно: ШІ не виявив автоматично всі проблеми. Зокрема, зіставлення ECTS і форматів експорту з ЛР 1 та питання, який запис оцінки є чинним, потребували аналізу вимог. Зауваження про змінюваний аргумент `exclude` не доводить фактичного псування даних, бо список у функції не змінюється; це ризик майбутньої модифікації.

Для ЛР 3 Codex запропонував класи, вхідні дані та очікування за Р-08/Р-17/Р-18, зафіксував їх до запуску, виконав тести й оформив результати. У пропозиції ШІ не було однозначної відповіді щодо стипендії для студента поза статусом `ACTIVE`; цей випадок позначено окремим ТВ-DT-19 як питання до замовника, а не доведений дефект реалізації. Так само «найближче» до межі середнє 89.5 обґрунтоване лише для двох цілих оцінок, не для довільної кількості. Студентці слід самостійно звірити модель і пояснити її на захисті; цей запис не стверджує, що вона вже провела незалежне порівняння з власним розв'язанням.
